01 · 프로젝트 개요

What is InterviewIQ?

혼자서도 모의 면접을 진행하고, 답변 내용과 비언어 행동을 함께 분석받는 실시간 멀티모달 면접 코칭 서비스. 면접 중 데이터를 5초 chunk로 저장·분석하고, 답변 단위(answer turn)로 묶어 꼬리질문/리포트를 만든다.

▌ 핵심 차별점
  • 최종 답변만 평가하지 않고, 5초 chunk로 시간 단위 데이터를 누적
  • 웹캠 전신 비언어 + 마이크 음성 + STT 텍스트를 chunkId 기준 병합
  • answer turn 단위로 묶어 꼬리질문·최종 리포트 생성
▌ 스택 한눈에
  • Frontend · Next.js · MediaPipe · vision/audio chunk 전송
  • Backend · FastAPI · Redis · Whisper · librosa
  • 분석 · RAG (기업/직무/공통) + LangGraph 5 agents
  • 저장 · 세션 종료 시 PostgreSQL 영구화

03 · 오늘 회의 (2026-05-25)

방향 전환 · Correction Loop

AI가 절대 평가를 하는 면접관이 아니라, 사용자 본인의 초기 상태와 비교해 시선 이탈·긴 침묵·자세 흔들림·답변 구체성이 어떻게 변했는지 보여주는 코칭으로.

→

Correction Loop

▌ 왜 좋은가
  • AI 절대 평가 신뢰도 문제 회피
  • "본인 대비 변화"라 설명이 안전
  • 발표 시 그래프·수치 시각화에 유리
▌ 기술 정당성 강화
  • MediaPipe → baseline·loop 동일 측정
  • Web Audio → 침묵/음량 비교
  • STT → transcript 비교 + 피드백
▌ 주의할 점
  • 질문이 달라지면 비교가 공정하지 않음
  • 답변을 외워 개선처럼 보일 수 있음
  • 지표 ≠ 실제 면접 역량 (단정 금지)

04 · before / after

무엇이 어떻게 바뀌었나

구조를 갈아엎는 것이 아니라, 기존 chunk·STT·RAG·LangGraph 위에 baseline + 교정 루프 레이어를 얹는 변화.

dimension ▼ BEFORE — 기존 방향 ▲ AFTER — 회의 후 새 방향
컨셉 한 번의 면접을 분석해 다음 질문/최종 피드백 제공 여러 회차를 비교해 사용자의 변화·개선 추세를 보여줌
평가 기준 현재 답변이 얼마나 적절한지 (절대 평가) 초기 baseline 대비 얼마나 변화했는지 (상대 비교)
UX 면접 1회 → 결과 확인 → 종료 연습 → 피드백 → 목표 선택 → 재연습 → 변화 확인 반복
최종 결과물 개별 면접 리포트 개별 리포트 + 회차별 비교 + 남은 약점 요약
세션 모델 session 만 존재 sessionType, loopIndex, groupId 추가
LLM 입력 chunk·STT 원문을 그대로 길게 넣을 위험 Write / Select / Compress / Isolate — baseline 요약·현재 목표만 선별 입력

06 · 핵심 비교 지표

baseline ↔ loop, 같은 방식으로 잰다

보조 지표를 욕심내지 않고 4개만 확실하게. 같은 측정 파이프라인을 유지해 비교 공정성을 확보.

▌ 01 · GAZE

시선 이탈

headForwardRatio 기반. 카메라를 향한 시간 비율이 낮은 구간을 looking_away 이벤트로 누적.

e.g. baseline 38% → loop 22%

▌ 02 · POSTURE

자세 흔들림

postureStability + upperBodyLeanIntensity. 흐트러진 시간 합계와 안정 구간 비율을 비교.

e.g. 6 → 4 구간

▌ 03 · SILENCE

긴 침묵

silenceDurationMs 임계치 초과 횟수. 답변 흐름이 끊긴 횟수와 총 침묵 시간으로 표현.

e.g. 5 → 2 회

▌ 04 · VOICE

말하기 비율 / 안정성

speakingRatio + energy 안정성. 답변 자체의 길이와 음량 변동성을 같이 본다.

e.g. 0.64 → 0.78

보조 지표 (filler word · 손/하체 움직임 · 말하기 속도 · 답변 길이) 는 MVP에선 측정만 하고 비교는 보류. 리포트에 노출하지 않는다.

07 · 세션 연결 방식

로그인 없이, groupId로 묶는다

baseline → loop → report를 한 세션으로 묶지 않고, 같은 그룹의 여러 세션으로 연결. 브라우저를 껐다 켜도 안 죽음.

// flow
1. 사용자 "면접 시작" 클릭
   → 백엔드: groupId = "g_a1b2c3" 발급
   → 프론트: localStorage.setItem('groupId', 'g_a1b2c3')

2. baseline 면접 종료 — 요약 계산
   → redis.SET group:g_a1b2c3:baseline {gazeAway:0.38,...} EX 7d

3. "교정 루프 시작" (브라우저 꺼도 OK)
   → 프론트: localStorage에서 groupId 꺼냄
   → POST /sessions/loop { groupId }
   → 백엔드: Redis에서 baseline 조회

4. loop 종료 → 비교 리포트
   → baseline + 이번 loop 요약 비교
▌ 핵심 결정
  • baseline + loop를 한 세션으로 묶지 않음
  • 변수/메모리 저장 ✗ · Redis 영속 저장 ✓
  • 로그인 없이 groupId + localStorage
▌ 가능
  • baseline 끝내고 브라우저 껐다 켜도 이어가기
  • 서버 재시작에도 데이터 유지
  • FastAPI worker 여러 개여도 OK
▌ 제약
  • 같은 브라우저·도메인
  • 시크릿 모드 ✗ · 데이터 삭제 ✗
  • Redis TTL 7일 후 새로 시작

08 · 리포트 표현 규칙

평가가 아니라, 관찰값으로 말한다

같은 데이터라도 단정적 평가로 쓰면 신뢰도 문제가 되돌아온다. "측정 결과 ~이 감지되었다 / 초기 대비 ~이 감소했다" 톤으로 통일.

▌ 쓰지 않을 표현
  • 나쁜 자세입니다 / 면접 태도가 좋지 않습니다
  • 긴장한 상태입니다 / 불안 감정이 보입니다
  • 합격 가능성이 높아졌습니다
  • 면접을 잘하게 되었습니다 / 태도가 좋아졌습니다
  • 정확한 시선 추적 / 감정 판별
▌ 권장 표현
  • 초기 측정에서 시선 이탈 구간이 감지되었습니다
  • 초기 측정 대비 긴 침묵 횟수가 줄었습니다
  • 이번 연습에서는 안정적인 구간이 늘었습니다
  • 상체 기울어짐이 감지된 시간이 있었습니다
  • 얼굴 방향 기반 주의 집중도 추정
발표 한 줄 · "AI가 사용자를 평가하는 면접관이 아니라, 첫 면접을 baseline으로 저장하고 반복 연습에서 자세·시선·침묵·음성 습관이 초기 대비 어떻게 변화했는지 보여주는 개인화 면접 코칭 서비스."
